# 怎么写这类片子的旁白与结构

目标不是"做了个视频"，而是**让一个没听过这件事的人在 15 分钟内明白谁在做什么，并且每一步都能自己核**。

## 结构模板（`story_v3.py` 用的就是这套）

| 段 | 镜数 | 干什么 |
| --- | --- | --- |
| 开场 | 3–4 | 说明方法：只用当事人原文、可核登记、公开网页；推断会打问号 |
| 一 · 把项目分开 | 8–12 | 讲清有几个主体，各自是什么、谁维护 |
| 二 · 把身份接起来 | 10–14 | 账号、产品名、域名怎么串成同一个运营方（关系网主场景） |
| 三 · 把矛盾摆出来 | 16–20 | 一处矛盾两镜（或一镜对撞板），每处都并排原话 |
| 四 · 提问 | 3 | 把前面所有矛盾收成三句话的问题（巨型 🤔） |
| 五 · 连问 | 10–12 | 一问一镜，编号 Q01…，每问带证据角标 |
| 六 · 猜测 | 5–7 | 只能猜的部分，全部写成问句 + 依据 |
| 收束 | 4–5 | 回顾方法、给观众可执行的建议、不加罪名 |

大约 90 镜 / 16 分钟。要短就砍第三节（只留 4–5 处最硬的矛盾）和第六节。

## 旁白的十二条规矩

1. **一句话一个事实**。15–40 字，超过 40 字切两句。
2. **先事实、后解释**。"他 11 月 3 日撤回了许可"（事实）→"这意味着之前的分发失去了依据"（解释，可留可删）。
3. **数字给人听**："2026 年 11 月 6 日"不要读成"二〇二六年十一月六日"，除非在片尾念日期。
4. **引用要归位**："他说——"后面直接上原文，不要转述成"他表示自己才是正主"。
5. **不替观众下结论**：把"这就是在割韭菜"换成"那么，这算不算把别人的产品，当成自己的来卖？"
6. **形容词尽量来自证据**：证据里写"完全知识产权"，就说"页面上写着完全知识产权"，别自己加"荒谬"。
7. **主语明确**：同一个"他"在同一段里只指一个人；换人就要换称呼。
8. **每镜留 0.55 秒呼吸**，这已经写进 `build.py`，旁白别写太满。
9. **不要在旁白里念图号**（"如图 13 所示"），图号放花字和角标。
10. **重复要有理由**：同一句关键原话可以说两次，一次在证据镜，一次在提问镜。
11. **片尾不号召针对个人**：给可执行建议（"用开源项目先看许可证""玩游戏认准官方渠道"）。
12. **写完念一遍**：中文旁白的口误在 TTS 里会被放大——尤其"的、地、得"和括号。

## 问题链怎么设计

好的提问段落不是"你觉得呢"，而是**把已经给过的事实重新组合成矛盾**：

```
现象 A（他说 X）
+ 现象 B（记录显示 Y）
+ 一句连接词（那么 / 如果 / 既然）
= 问题（为什么 X 和 Y 能同时成立？）
```

`bigq` 场景的字段就是这个结构：`text` 是问题，`sub` 是一句压缩的对照，`ev` 是证据角标（`图13 / 图14`）。

## 猜测卡怎么写

只有当你**确实不知道动机**、但事实允许一种解释时才用。

```python
A(media("S76", "guess", "旁白：如果不是为了流量，那图的是什么？",
        index="01",
        guess="借名：让「Chronodivide」这四个字，替自己的产品说话？",
        basis="chronodivide.cn 自称独立知识产权；王二火大官网把 Chronodivide 指向它；图13 说「国际版项目名」"))
```

- 标题必须带问号；
- `basis` 必须能指回具体图号或网页原文；
- 不要写"显然""唯一解释"；
- 每条猜测后面最好跟一镜"你可以不同意我们的解读"。

## 口径（硬约束）

- 只陈述不定性：禁用"侵占 / 盗用 / 抢注 / 投毒 / 洗白 / 皮包公司"。对方原话可以加引号引用，并标明是谁说的。
- 不点名真实姓名、不汇总一个人的多平台账号；可以用公开的账号名、产品名、公司名。
- 双方说法要完整出现，不截取。
- 有打码要求的截图，自制场景里必须自己按 `assets.json` 的 `redact` 模糊（`scenes3.load_asset()` 已经做了）。
- 网页摘录要么画成浏览器窗口并标 URL + 抓取日期，要么不要用——**不伪造截图**是这类内容的底线。
