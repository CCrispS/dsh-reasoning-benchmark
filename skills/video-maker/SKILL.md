# 视频创造者

本技能只服务一个题材：Chrono Divide 和 vera20k 两个项目的作者，与网页红警一方之间的授权与署名争议。视频的任务是把公开记录和双方说法讲清楚，让观众自己判断，不替观众下结论。事实、证据图、口径和一套现成分镜都已经在技能里，拿到任务后从制作简报和事实表开始即可。

可以交付两样东西：

1. **分镜稿**：按用户指定的风格，改编现成分镜或新写一套（完整版、事件速览、单个争议点专题）。
2. **成片**（可选）：用 `scripts/` 里的渲染器，把分镜里的证据图、字卡、旁白直接合成 mp4。

## 技能里有什么

| 路径 | 内容 | 什么时候看 |
| --- | --- | --- |
| `references/case-brief.md` | 制作简报：叙述结构、50 张证据图索引与可用分级、口径、各风格改编建议 | **每次开工先读** |
| `facts.md` | 事实表：当事方、时间线、每个争议点双方的说法、未证实事项；每条都标明来源和证据图 | **每次开工先读**，写旁白时随时查 |
| `assets/` | 50 张证据截图（`img01.png`…`img50.png`）和清单 `assets.json` | 写分镜引用“图N”、出片 |
| `storyboards/full.md` | 完整版说明视频分镜 | 改编或挑镜头 |
| `render/full.json` | 上面分镜的渲染规格，可直接出片 | 出片 |
| `references/styles.md` | 13 种视频风格的参数 | 换风格、写风格卡 |
| `references/shot-language.md` | 画面类型词表、运镜、景别、转场、时长换算 | 写分镜 |
| `references/templates.md` | 交付文档结构 | 组织交付物 |
| `references/rendering.md` | 出片步骤、渲染 JSON 规范、排错 | 出片 |
| `scripts/` | 环境检查、分镜检查、分镜转渲染规格、渲染、docx 抽取 | 见下文 |

## 安装与环境

- **放哪里都行**：把整个文件夹放进所用 AI 工具的技能目录（例如 Claude Code 的 `~/.claude/skills/`），或者把 `SKILL.md` 和需要的参考文件交给任何能读文件的 AI。文中路径都相对于本技能根目录。
- **脚本只依赖 Python 3.8+ 标准库和 ffmpeg**，macOS、Windows、Linux 通用。Windows 把命令里的 `python3` 换成 `python`。
- **只写分镜不需要安装任何东西。** 出片前先检查环境：
  ```bash
  python3 scripts/setup_env.py
  ```
  加 `--install` 会安装便携版 ffmpeg（`imageio-ffmpeg`），系统没有中文字体时下载开源字体 Noto Sans SC 到技能的 `fonts/` 目录；它会先列出要做的事，然后直接执行。

## 工作流程

### 第 1 步：读制作简报和事实表

读 `references/case-brief.md` 和 `facts.md`。简报告诉你怎么讲、每张图能证明什么、哪些话不能说；事实表告诉你发生了什么、谁说的。后面每一步都以这两份文件为准。

### 第 2 步：确认需求

只在答案会明显改变结果、又无法从上下文推断时才问用户，而且一次问完；其余用默认值，并写进交付物的“项目概要”。

| 参数 | 用户没说时 |
| --- | --- |
| 视频风格 | 解说（与现成分镜一致） |
| 平台与画幅 | 横屏 16:9；用户指定竖屏时用 9:16 |
| 时长 | 按 `styles.md` 速查表的常规时长 |
| 交付 | 说“分镜”出分镜稿；说“出片”“生成视频”再渲染 |
| 形态 | 一条完整说明视频；用户要短的就出 1–3 分钟事件速览或单个争议点专题。不做系列，不做以引流为目的的切片 |

用户对风格只给模糊描述时（“高级感”“像纪录片”“节奏快一点”），按 `styles.md` 末尾的对照表落成具体参数。

### 第 3 步：决定复用还是新写

- **只换包装**（画幅、主题、配音、配乐、去掉字幕）：不用改分镜。直接用 `render/full.json` 出片，或用 `md2render.py --style-meta` 重新生成规格。
- **换风格、结构可用**：以 `storyboards/full.md` 为底改写。调整镜长、语速、开场方式、旁白口吻和镜头取舍，镜号重新编。
- **新形态**（事件速览、英文版、单个争议点专题）：按制作简报第 5 节的改编建议，从证据图索引里选图，新写分镜。

### 第 4 步：写风格卡

从 `references/styles.md` 选风格，落成一张风格卡：平台与画幅、时长、平均镜长、旁白语速与口吻、开场方式、画面基调、字幕与花字、配乐与音效、转场。写分镜拿不准时回来查风格卡。

### 第 5 步：规划结构，再写镜头

1. 按制作简报第 1 节定讲哪几个争议点、每部分多长。每个争议点都按“原作者或记录 → 网页红警方的说法 → 能确认什么”的顺序安排。
2. 算旁白字数预算：时长 × 语速。中文语速：慢 3.5 字/秒（纪录片），中 4.5 字/秒（解说），快 5.5–6 字/秒（短视频）。镜头时长 ≥ 旁白字数 ÷ 语速 + 0.5 秒。

### 第 6 步：写分镜表

所有风格都用这 8 列。列名和写法也是渲染器的输入约定，照着写才能直接出片：

```
| 镜号 | 时长 | 画面类型 | 运镜 | 画面内容 | 旁白/台词 | 字幕/花字 | 声音/备注 |
```

| 列 | 写法 |
| --- | --- |
| 镜号 | 完整版用“章-序号”（`2-05`），速览和专题用“S-序号” |
| 时长 | 秒数 |
| 画面类型 | 截图、照片、档案、字卡、章节卡、引文卡、数据卡、分屏、时间线、标题卡、片尾；需另外制作的写实拍、录屏、动画、出镜。见 `shot-language.md` |
| 运镜 | 固定、缓推、缓拉、左移、右移、下移（长截图向下滚）、上移 |
| 画面内容 | 用“图N”引用证据，并写清重点：“图32，红框圈出 I did not authorize it.” |
| 旁白/台词 | 口语化短句，一句一个信息；按 `facts.md` 的来源标签说明是谁说的；原话加引号 |
| 字幕/花字 | 屏幕上额外的文字。`／` 分主副标题，`；` 分列表项，分屏左右用 `｜` |
| 声音/备注 | 配乐和音效只在变化处写；打码、待补素材也写这里 |

写镜头的原则：一镜一个信息点；说到哪条事实，画面就是哪张证据；截图至少停 4 秒，长截图用“下移”；每 30–60 秒换一次画面类型；章节之间用章节卡或音乐变化分隔；结尾回顾记录和仍有分歧的地方。

### 第 7 步：口径检查与自检

先按制作简报第 3 节逐条核对口径，再运行：

```bash
python3 scripts/storyboard_check.py 你的分镜.md --speed 4.5 --images 50
```

它会统计每张表的时长、列出旁白超速的镜头和没用到的图。然后核对：

- 时长与目标相差不超过 ±10%；
- 每个事实陈述都有证据画面，来源说法与 `facts.md` 的标签一致，【未证实】的内容没有说成事实；
- 每个争议点都呈现了网页红警方的说法；
- 没有定性词、历史类比和嘲讽性的花字或音效，没有提任何人的真实姓名；
- 没用到图33、图38；用了图43或图44时，相邻镜头里有图45。

### 第 8 步：交付

- 分镜按 `references/templates.md` 的结构组织，默认 Markdown 表格；要表格文件时加 `--csv 输出目录` 导出 CSV。
- 新分镜存进 `storyboards/`，文件名写明风格或用途（例如 `overview-3min.md`、`documentary.md`）。

## 出片

读 `references/rendering.md`，流程概要：

1. `scripts/md2render.py` 把分镜表转成渲染规格。
2. 需要时在 JSON 里补高亮框坐标、换外部素材（写进 `media`）、指定真人配音文件（`audio`）。
3. `scripts/render_video.py` 合成 mp4：截图运镜、字卡、逐句字幕、配音、配乐、自动打码。用 `-o` 和 `--work` 把成片和缓存放到技能目录之外。配音比镜头长时会先保调加速贴合分镜，再不够才延长镜头。
4. 先加 `--sheet` 输出逐镜拼图，自己检查顺序、文字和打码，再交付。
5. 交付时说明哪些镜头还是“待补素材”占位卡，并提醒用户：你只看了拼图，节奏和声音要实际播放确认。

## 素材更新时

如果用户提供了新的证据截图或新版文档（docx）：

```bash
python3 scripts/extract_docx.py 新文档.docx ../新文档抽取
```

对照新抽出的正文和插图，更新 `assets/`（保留已有编号和打码设置，新图往后编号并补进 `assets.json`）、`facts.md`（新事实按来源标签登记）和 `references/case-brief.md` 的证据图索引。
